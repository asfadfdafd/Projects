# Структура демо-датасета

Файл: `data/cases.csv` — 4000 синтетических гражданских дел (РК).
Генератор: `scripts/generate_dataset.py`, зерно `20260809` (воспроизводимо).

> **Данные синтетические.** Реальные судебные акты не использовались.
> Веса признаков заданы разработчиком по представлениям о практике
> доказывания, а не извлечены из корпуса решений.

## Как устроена генерация

Не случайный шум, а явная причинная модель:

```
сила_позиции = свободный_член
             + Σ (вес_признака × значение)
             + взаимодействия
             + шум ~ N(0; 1.05)

P(иск удовлетворён) = sigmoid(сила_позиции)
исход                ~ Bernoulli(P)
```

Три следствия, важные для демонстрации:

1. **Важности признаков осмысленны.** Обученная модель находит те же факторы,
   которые заложены в генератор, — это видно на странице «Как устроена модель».
2. **Есть эталон для проверки.** Колонка `true_probability` содержит «истинную»
   вероятность и в обучении не участвует. Корреляция прогноза с ней — 0,98:
   модель восстановила структуру, а не подогналась под шум.
3. **Шум задан осознанно.** Стандартное отклонение 1,05 в логарифме шансов
   отражает неустранимую неопределённость: усмотрение суда, устные пояснения,
   поведение сторон в заседании. Без него ROC-AUC был бы близок к единице,
   что для такой задачи означало бы ошибку, а не успех.

## Колонки

### Идентификатор

| Колонка | Тип | Описание |
|---|---|---|
| `case_id` | строка | Уникальный номер демо-дела |

### Параметры дела

| Колонка | Тип | Значения / диапазон |
|---|---|---|
| `dispute_category` | категория | `debt_contract`, `labor`, `consumer`, `insurance`, `construction`, `housing_rent`, `damage`, `family_property` |
| `claimant_type` | категория | `individual`, `entrepreneur`, `legal_entity` |
| `respondent_type` | категория | то же |
| `court_instance` | категория | `first`, `appeal` (17 % апелляций) |
| `claim_amount_kzt` | число | 120 тыс. — 400 млн тг, логнормальное распределение |
| `months_since_breach` | целое | 1–240 месяцев с момента нарушения |

### Документы и доказательства

| Колонка | Тип | Описание |
|---|---|---|
| `has_written_contract` | 0/1 | Письменный договор в деле |
| `contract_signed_both` | 0/1 | Подписан обеими сторонами (осмыслен только при наличии договора) |
| `has_payment_documents` | 0/1 | Платёжные поручения, квитанции, выписки |
| `has_acceptance_act` | 0/1 | Акты приёма-передачи, накладные, акты сверки |
| `has_correspondence` | 0/1 | Переписка сторон |
| `has_expert_opinion` | 0/1 | Заключение эксперта или отчёт об оценке |
| `witness_count` | целое | 0–5 свидетелей |
| `evidence_count` | целое | 1–40 документов в деле |
| `doc_completeness` | 0–1 | Доля присутствующих типов подтверждающих документов |

### Процессуальные факторы

| Колонка | Тип | Описание |
|---|---|---|
| `pretrial_claim_sent` | 0/1 | Досудебная претензия направлена |
| `limitation_period_ok` | 0/1 | Срок исковой давности не истёк (общий срок — 3 года; учитывается перерыв) |
| `claimant_has_lawyer` | 0/1 | У истца есть представитель |
| `respondent_has_lawyer` | 0/1 | У ответчика есть представитель |
| `respondent_appeared` | 0/1 | Ответчик участвует в процессе |
| `respondent_admits_partially` | 0/1 | Частичное признание требований |
| `counterclaim_filed` | 0/1 | Подан встречный иск |

### Целевые переменные

| Колонка | Тип | Описание |
|---|---|---|
| `outcome_win` | 0/1 | **Основная цель.** Требования удовлетворены полностью или частично |
| `satisfied_share` | 0–1 | Доля удовлетворённых требований (задел под вторую модель) |
| `outcome_label` | категория | `satisfied_full` / `satisfied_partial` / `denied` |
| `true_probability` | 0–1 | Служебная: истинная вероятность из генератора. **В обучении не используется** |

## Что получилось в наборе

Общая доля удовлетворённых исков — **60,8 %**
(полностью 31,7 %, частично 29,1 %, отказано 39,2 %).

| Категория спора | Дел | Доля удовлетворённых | Медианная сумма |
|---|---:|---:|---:|
| Взыскание задолженности по договору | 901 | 74,5 % | 1 713 474 тг |
| Договор подряда / качество работ | 425 | 72,7 % | 2 972 355 тг |
| Страховой спор (выплата) | 465 | 67,3 % | 1 300 905 тг |
| Жилищный спор / аренда | 376 | 59,3 % | 1 095 060 тг |
| Защита прав потребителей | 506 | 57,5 % | 499 767 тг |
| Трудовой спор | 496 | 53,8 % | 851 085 тг |
| Возмещение ущерба (ДТП, залив) | 531 | 48,2 % | 1 487 872 тг |
| Раздел имущества супругов | 300 | 33,7 % | 4 805 458 тг |

Разброс между категориями заложен намеренно: набор, где все категории дают
одинаковые 60 %, выглядел бы искусственно и не позволял бы модели выучить
влияние категории спора.

## Заложенные корреляции

Признаки генерируются не независимо — иначе набор был бы нереалистичным:

* юридические лица чаще имеют полный пакет документов и представителя;
* по крупным требованиям обе стороны чаще привлекают юристов и экспертизу;
* по деликтным спорам (залив, ДТП) договор отсутствует почти всегда,
  а вес экспертизы, наоборот, максимален;
* по трудовым спорам растёт вес свидетельских показаний;
* пропуск срока исковой давности возникает только там, где обращение
  в суд действительно отложено на годы (17 % дел с длительной задержкой).

## Замена на реальные данные

Схема специально описана в одном месте — `core/schema.py`. Чтобы перейти
на реальный корпус:

1. привести реальные карточки дел к колонкам выше;
2. заменить `data/cases.csv`;
3. запустить `python3 scripts/train_model.py`.

Ни код извлечения признаков, ни интерфейс менять не потребуется.
