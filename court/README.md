# AI-помощник по гражданским делам — демонстрационный прототип

Два модуля на общем ядре:

* **Модуль 1 «Оценка шансов»** — для гражданина без юридического образования.
  Загружает документы, получает ориентировочную вероятность удовлетворения
  иска, **ожидаемую сумму взыскания**, перечень повлиявших обстоятельств,
  **похожие дела из базы с их исходами** и рекомендации.
* **Модуль 2 «Анализ дела»** — для судьи. Загружает материалы дела целиком,
  получает структурированный обзор, хронологию, **автоматически найденные
  расхождения между позициями сторон**, спорные точки с цитатами
  и вопросы сторонам.

Принимаются файлы **txt, docx, rtf и pdf** (doc и сканы — при наличии
системных утилит).

> **Это демонстрационный прототип.** Модель обучена на синтетическом наборе
> данных и не отражает реальную судебную практику. Результаты не являются
> юридической консультацией, прогнозом решения суда или основанием для
> процессуальных действий.

## Запуск

```bash
python3 scripts/generate_dataset.py    # сгенерировать демо-датасет
python3 scripts/train_model.py         # обучить модель (около 3 секунд)
python3 app.py                         # http://127.0.0.1:8000
```

Проверка, что всё работает:

```bash
python3 scripts/smoke_test.py          # 83 сквозные проверки
python3 scripts/test_documents.py      # разбор docx, rtf, pdf
```

**Зависимостей у рантайма нет.** Нужен только Python 3.8+ из коробки.
`numpy` требуется исключительно для обучения модели; сама модель
выгружается в обычный JSON, и инференс работает на чистом Python.
Интерфейс не подключает ни одной внешней библиотеки и ни одного CDN —
демо целиком работает офлайн, в том числе без интернета в зале.

## Что показывать на демонстрации

В интерфейсе есть три готовых дела — загружать реальные документы
на показе не требуется.

| Дело | Что демонстрирует | Оценка модуля 1 |
|---|---|---|
| Взыскание задолженности по договору поставки | Сильная позиция: договор, накладные, акт сверки, признание долга в переписке | **91 %** |
| Возмещение ущерба от залива квартиры | Средняя позиция: есть акт и оценка, но причина и размер оспариваются | **45 %** |
| Взыскание невыплаченной заработной платы | Слабая позиция: документов нет, пропущен срок обращения | **2 %** |

Разброс от 2 % до 91 % на трёх делах виден сразу — это и есть основной
сюжет показа.

Рекомендуемый сценарий на 5 минут:

1. Главная → **Модуль 1** → открыть дело о заливе (45 %).
2. Показать блоки «что работает на вас» / «что ослабляет позицию» —
   каждый фактор с числом в процентных пунктах.
3. Блок «Сколько можно получить по итогу»: заявлено 1,78 млн, при выигрыше
   около 1,46 млн, с учётом вероятности — 0,65 млн. Именно это интересует
   человека, а не проценты.
4. Блок «Похожие дела в базе»: из 60 близких дел удовлетворено примерно
   столько же процентов, сколько дала модель. Оценка проверяется простым
   подсчётом — это снимает вопрос «откуда цифра».
5. Показать блок «что система нашла в документах»: у каждого признака есть
   цитата-основание, любой признак можно поправить чекбоксом и пересчитать
   оценку. Это снимает главное возражение — «чёрный ящик».
6. Открыть трудовое дело (2 %) — красный блок про пропуск срока: система
   не советует «донести документы», когда это не поможет.
7. Переключиться на **Модуль 2**, открыть дело о поставке: раздел
   «Расхождения в материалах сторон» — истец требует 4 850 000 тг,
   ответчик признаёт 3 100 000 тг, обе цитаты рядом. Ниже — спорные точки,
   хронология, вопросы сторонам (кнопки «скопировать» и «распечатать»).
8. Трудовое дело в **Модуле 2**: расхождение по окладу (780 000 против
   210 000) и прямое противоречие «приказ вручён» / «приказ не вручался».
9. Страница **«Как устроена модель»** — метрики, калибровка, границы
   применимости. Для аудитории, которая спросит «а насколько это точно».

## Три решения, которые стоит проговорить на показе

**Логистическая регрессия, а не нейросеть.** Вклад каждого обстоятельства
считается точно (`коэффициент × значение`), а не аппроксимируется. На тех же
данных градиентный бустинг дал ROC-AUC 0,819 против 0,824 у регрессии —
выигрыша нет, а объяснимость теряется. Обе модели обучаются в
`scripts/train_model.py`, метрики обеих лежат в `models/metrics.json`.

**Судье вероятность исхода не показывается.** Оценка шансов нужна стороне,
которая решает, идти ли в суд. Тот же показатель перед заседанием — это уже
воздействие на внутреннее убеждение. Модуль 2 даёт карту материалов и
вопросы; вывод по делу остаётся за судьёй. Проверяется автотестом.

**Пользователь может исправить извлечённые данные.** Правиловое извлечение
ошибается. Каждый признак сопровождается цитатой-основанием, любой можно
поправить и увидеть пересчёт. Без этого система остаётся чёрным ящиком
независимо от качества модели.

## Качество модели

Проверочная выборка — 800 дел, в обучении не участвовали.

**Удовлетворят ли иск** (бинарная классификация):

| Модель | ROC-AUC | F1 | Accuracy | Brier | Log loss |
|---|---:|---:|---:|---:|---:|
| Логистическая регрессия | 0,824 | 0,784 | 0,738 | 0,167 | 0,499 |
| Градиентный бустинг | 0,819 | 0,779 | 0,735 | 0,171 | 0,510 |

Средневзвешенное расхождение прогноза с фактом по калибровочным корзинам —
**5,0 п.п.** Именно эта величина показывается пользователю как диапазон
оценки: заявлять точность до процента у модели нет оснований.

**Какую долю требований удовлетворят** (регрессия на выигранных делах):

| Показатель | Значение |
|---|---:|
| Средняя ошибка (MAE) | 0,139 |
| Если всегда предсказывать среднее | 0,172 |
| Выигрыш к простому среднему | 19 % |
| R² | 0,242 |

R² скромный, и это ожидаемо: размер присуждённого зависит от обстоятельств,
которых в карточке дела нет. Поэтому ошибка модели (±14 п.п.) показывается
пользователю рядом с суммой, а не прячется.

Корреляция прогноза с «истинной» вероятностью генератора (в обучении
не участвует) — **0,97**: модель восстановила заложенную причинную
структуру, а не подогналась под шум.

Наиболее влиятельные факторы (падение ROC-AUC при перемешивании признака):

| Фактор | Падение ROC-AUC |
|---|---:|
| Срок исковой давности не истёк | 0,047 |
| Полнота пакета документов | 0,027 |
| Давность обращения в суд | 0,023 |
| Договор подписан обеими сторонами | 0,021 |
| Ответчик частично признаёт требования | 0,018 |

## Ограничения

* Данные синтетические. Перенос на практику требует переобучения на корпусе
  реальных исходов — схема данных и код к этому готовы, см. `ARCHITECTURE.md`.
* Правиловый поиск расхождений находит спор по суммам и прямые
  противоречия «есть / нет». Смысловые противоречия, выраженные без
  общих ключевых слов, он пропустит — здесь языковая модель дала бы
  заметно больше.
* Извлечение признаков правиловое: устойчиво и работает офлайн, но хуже
  языковой модели справляется с нетиповыми формулировками. Интерфейс
  `Extractor` рассчитан на замену реализации без изменения остального кода.
* PDF разбирается встроенным разборщиком без внешних библиотек; на
  сложной вёрстке он уступает pypdf, который подхватывается автоматически,
  если установлен. Сканы требуют tesseract в системе.
* Похожие дела ищутся по синтетической базе: механика настоящая,
  статистика — нет.
