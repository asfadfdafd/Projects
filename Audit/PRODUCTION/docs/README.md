# MVP Sales Bot — поставка по плану (Фаза 0/1, раздел 9)

Реализация пунктов 1–3 раздела 9 `MVP_Audit_Sales_Bot_Plan.md`. Все цены, анкета и договор — **плейсхолдеры** из Sample-файлов; заменяются данными аудитора без правки кода (цены — прямо в БД).

## Состав

| Файл | Что это |
|---|---|
| `01_sales_funnel_migration.sql` | Миграция БД: расширение `nnn_leads`/`nnn_messages`, новые таблицы `nnn_services`, `nnn_pricing_rules`, `nnn_questionnaire_responses`, `nnn_proposals`, `nnn_contracts`, `nnn_faq_kb` + сиды-плейсхолдеры. Идемпотентна. |
| `NNN Sales Bot — воронка продаж (Telegram).json` | Главный воркфлоу: state machine, FAQ-консультант (Groq + база знаний), пошаговая анкета (12 вопросов), отправка КП с кнопками, генерация договора, алерты команде. |
| `NNN Pricing Engine (под-воркфлоу).json` | Движок цены: правила из БД считают число детерминированно, Groq пишет только текст КП. Флаг ручной проверки при цене > порога. |

## Установка (порядок важен)

1. **SQL**: выполнить `01_sales_funnel_migration.sql` в базе "Social Automation DB" (та же, что у NNN-воркфлоу).
2. **Импорт** в n8n: сначала Pricing Engine, затем Sales Bot.
3. В узле **«🧮 Движок цены (КП)»** главного воркфлоу выбрать импортированный под-воркфлоу (поле Workflow).
4. В трёх **Gmail-узлах** заменить `team@example.com` на адрес команды.
5. **Отключить/выключить** старый `NNN Telegram Bot — приём документов и запись` (оба слушают одного бота — будут конфликтовать). Старый паркуем до Фазы 3.
6. Активировать оба новых воркфлоу. Креденшлы (Telegram, Postgres, Groq, Gmail) переиспользуются существующие — ничего создавать не нужно.

## Как работает state machine

Состояние лида хранится в `nnn_leads.state`:
`greeting → faq → awaiting_questionnaire → pricing → proposal_sent → contract_sent` (+ `negotiating`).
Роутер на каждое сообщение: кнопки (callback) имеют приоритет; «хочу заказать аудит» → анкета; в `awaiting_questionnaire` любой текст — ответ на текущий вопрос; в `proposal_sent` «да/согласен» или кнопка → договор; иначе FAQ.

## Что заменить перед боевым запуском (плейсхолдеры)

- `nnn_services.base_price`, `nnn_pricing_rules` — реальные цены/коэффициенты (UPDATE в БД, код трогать не надо).
- `nnn_faq_kb` — реальные факты: № лицензии, сроки, условия.
- Вопросы анкеты — массив `QUESTIONS` в узле «✍️ Записать ответ» (id полей менять синхронно с движком цены).
- Шаблон договора — узел «📄 Сгенерировать договор» (город, наименование, представитель).
- Email команды в Gmail-узлах.

## Сознательные ограничения MVP (по плану)

- Договор уходит **.txt-файлом**, э-подпись — плейсхолдер до выбора провайдера (DocuSign/SignNow, раздел 6 п.5). Состояние `signed` появится с вебхуком провайдера.
- Instagram-адаптер — Фаза 2: узел «🧩 Нормализовать вход» уже выдаёт единый формат, адаптер Meta подключится к «🔎 Лид + состояние».
- FAQ не использует историю переписки (логируется в `nnn_messages`, подключить контекст — мелкая доработка).
- Если состояние `awaiting_questionnaire` есть, а строки анкеты нет (ручное вмешательство в БД), ветка молча остановится — лечится повторным «хочу заказать аудит».

## Проверка формулы цены (сошлось с примерами прайса)

- Инициативный, малый: **₸300 000** ✓
- Обязательный, МСФО, средний: 897 000 → **₸900 000** ✓
- Недропользователь, крупный, 2 года, срочно: 3 894 000 → **₸3 900 000** ✓ (ниже порога ручной проверки 5 млн)
