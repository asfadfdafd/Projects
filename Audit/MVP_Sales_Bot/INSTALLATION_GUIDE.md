## Шаг 1 — Запустить SQL-миграцию

**Файл:** `01_sales_funnel_migration.sql`

Это расширение существующей базы данных под воронку продаж. Миграция **идемпотентна** — запускать можно только один раз, повторный запуск не навредит.

### Что делает миграция

- Добавляет поля `channel`, `state`, `phone`, `company_name`, `contact_name` в таблицу `nnn_leads`
- Создаёт 6 новых таблиц: `nnn_services`, `nnn_pricing_rules`, `nnn_questionnaire_responses`, `nnn_proposals`, `nnn_contracts`, `nnn_faq_kb`
- Заполняет таблицы тестовыми плейсхолдерами (цены, FAQ, коэффициенты)

### Как запустить

**Вариант A — через pgAdmin / DBeaver (рекомендуется):**

1. Откройте ваш инструмент для работы с Postgres.
2. Подключитесь к базе «Social Automation DB» (те же реквизиты, что в n8n).
3. Откройте файл `01_sales_funnel_migration.sql` или скопируйте его содержимое в редактор запросов.
4. Выполните весь файл целиком (кнопка «Run» / F5).
5. Убедитесь, что ошибок нет. Ожидаемый результат — серия сообщений `ALTER TABLE`, `CREATE TABLE`, `INSERT`.

**Вариант B — через терминал:**

```bash
psql -h ВАШ_ХОСТ -U ВАШ_ПОЛЬЗОВАТЕЛЬ -d ВАШ_БД -f 01_sales_funnel_migration.sql
```

**Проверка:** выполните запрос — должно вернуть строки:

```sql
SELECT code, name_ru, base_price FROM nnn_services;
SELECT factor, condition, value FROM nnn_pricing_rules ORDER BY id;
SELECT topic FROM nnn_faq_kb;
```

## Шаг 2 — Импортировать «Pricing Engine» (движок цены)

**Файл:** `NNN Pricing Engine (под-воркфлоу).json`

> ⚠️ Этот воркфлоу нужно импортировать **первым** — главный бот вызывает его как подпроцесс. Если импортировать в обратном порядке, ссылка не установится.

### Как импортировать

1. В n8n откройте меню **≡ → Workflows → Import from file**.
2. Выберите файл `NNN Pricing Engine (под-воркфлоу).json`.
3. Нажмите **Import**.
4. После импорта воркфлоу откроется. **Запомните его название** — оно понадобится на шаге 4.
5. **Активируйте** воркфлоу (переключатель вверху справа → Active).

## Шаг 3 — Импортировать главный «Sales Bot»

**Файл:** `NNN Sales Bot — воронка продаж (Telegram).json`

1. В n8n откройте меню **≡ → Workflows → Import from file**.
2. Выберите файл `NNN Sales Bot — воронка продаж (Telegram).json`.
3. Нажмите **Import**.

После импорта воркфлоу откроется. Пока **не активируйте** — сначала настройте (шаги 4–6).

## Шаг 4 — Привязать движок цены к главному боту

В главном воркфлоу Sales Bot найдите узел **«🧮 Движок цены (КП)»**:

1. Кликните на узел.
2. В поле **Workflow** нажмите на выпадающий список.
3. Найдите и выберите **«NNN Pricing Engine»** (воркфлоу, импортированный на шаге 2).
4. Сохраните узел.

## Шаг 5 — Заменить email команды

В главном воркфлоу найдите **три узла Gmail** и замените адрес `team@example.com` на реальный email вашей команды:

| Узел | Что делает |
|---|---|
| «📨 Алерт: новый лид» | Уведомляет команду о новом клиенте |
| «📨 Алерт: анкета заполнена» | Сигнал, что клиент прошёл анкету |
| «📨 Алерт: КП > порога» | Предупреждение, когда цена выше ₸5 млн (требует ручного одобрения) |

В каждом узле: кликните → поле **Send To** → вставьте адрес → сохраните.

## Шаг 6 — Отключить старый бот

> ⚠️ Старый «NNN Telegram Bot — приём документов и запись» и новый Sales Bot **слушают одного Telegram-бота**. Если оба активны — они будут конкурировать за сообщения и отвечать дважды.

1. В n8n откройте воркфлоу **«NNN Telegram Bot — приём документов и запись»**.
2. Переведите переключатель вверху в положение **Inactive**.
3. Воркфлоу сохраняется — его можно вернуть позже (Фаза 3, когда понадобится функционал приёма документов).

## Шаг 8 — Заменить плейсхолдеры (перед боевым запуском)

Воркфлоу работает с тестовыми данными. До реального использования замените их:

### 8.1 Цены и коэффициенты (в БД, код трогать не нужно)

Выполните UPDATE-запросы в базе данных:

```sql
-- Базовые цены услуг (пример — подставьте реальные)
UPDATE nnn_services SET base_price = 350000 WHERE code = 'voluntary';
UPDATE nnn_services SET base_price = 450000 WHERE code = 'tax';
UPDATE nnn_services SET base_price = 600000 WHERE code = 'statutory';
UPDATE nnn_services SET base_price = 800000 WHERE code = 'due_diligence';
UPDATE nnn_services SET base_price = 1200000 WHERE code = 'subsoil';

-- Порог ручной проверки (сейчас ₸5 млн)
UPDATE nnn_pricing_rules SET value = 5000000
  WHERE rule_type = 'config' AND factor = 'review_threshold';
```

Все остальные коэффициенты (`revenue_band`, `employees`, `urgency`, `extra_year` и т.д.) — в таблице `nnn_pricing_rules`. Обновляйте через UPDATE по полю `factor`+`condition`.

### 8.2 База знаний FAQ

```sql
-- Обновить факты, которые бот использует в ответах
UPDATE nnn_faq_kb SET content = 'Реальный текст про лицензию...' WHERE topic = 'Лицензии';
UPDATE nnn_faq_kb SET content = 'Реальный текст про сроки...'   WHERE topic = 'Сроки';

-- Добавить свои темы
INSERT INTO nnn_faq_kb (topic, content) VALUES
  ('Команда', 'Текст про команду аудиторов...'),
  ('Клиенты', 'Текст про опыт и клиентов...');
```

### 8.3 Вопросы анкеты

В главном воркфлоу откройте узел **«✍️ Записать ответ»** → в коде найдите массив `QUESTIONS`. Отредактируйте вопросы: текст (`text`), идентификатор (`id`) и тип (`type`). Идентификаторы полей должны совпадать с полями, которые читает движок цены — не меняйте `id` стандартных полей (`audit_type`, `revenue_band`, `employees` и т.д.) без синхронного обновления Pricing Engine.

### 8.4 Шаблон договора

В главном воркфлоу откройте узел **«📄 Сгенерировать договор»** → замените плейсхолдеры в шаблоне:

- `[НАЗВАНИЕ КОМПАНИИ-АУДИТОРА]` → реальное наименование
- `[ГОРОД]` → ваш город (Алматы / Астана / ...)
- `[ФИО РУКОВОДИТЕЛЯ]` → ФИО и должность подписанта
- `[ОСНОВАНИЕ]` → Устав / доверенность

## Шаг 9 — Тестирование

Перед боевым запуском проверьте каждый сценарий вручную через Telegram:

| Сценарий | Что проверить |
|---|---|
| Написать боту «Привет» | Получить приветствие |
| Написать «Сколько стоит аудит?» | FAQ-ответ про цены без анкеты |

**Проверка в БД после тестов:**

```sql

SELECT id, channel_id, state, company_name FROM nnn_leads ORDER BY created_at DESC LIMIT 5;
```

## Частые проблемы

**Бот не отвечает после активации**
→ Проверьте, что старый «NNN Telegram Bot» деактивирован (шаг 6). Два активных бота на одном Telegram-токене блокируют друг друга.

**Ошибка «Workflow not found» в узле «Движок цены»**
→ Вернитесь к шагу 4: в узле «🧮 Движок цены (КП)» должен быть явно выбран импортированный Pricing Engine.

**Цена считается как 0 или NaN**
→ Убедитесь, что SQL-миграция выполнена успешно и таблица `nnn_pricing_rules` содержит строки. Проверьте запросом: `SELECT COUNT(*) FROM nnn_pricing_rules;` — должно быть ≥ 13.

**Gmail-узел падает с ошибкой авторизации**
→ В узле заново выберите Gmail-креденшл через Credentials → переподключите OAuth.

**Состояние лида не меняется (`state` остаётся `greeting`)**
→ Убедитесь, что поля `state`, `channel` добавлены в `nnn_leads` (миграция шага 1). Проверьте: `\d nnn_leads` в psql или через pgAdmin.
